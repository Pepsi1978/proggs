# R8 — Best Practices (Stand 2026-06-03, AGP 8.7.3 / R8 8.7.x + AGP 8.10.0 / R8 8.10.x)

Die „so-macht-man-es-richtig"-Seite zum Bug-Almanach `~/proggs/bugs/android-build/r8.md`. R8 ist Androids
Code-Shrinker/Optimizer/Obfuscator (mit AGP gebündelt, **Full-Mode Default seit AGP 8.0**). Ziel
dieser Datei: R8 so einführen, konfigurieren und VOR dem Play-Store-Upload verifizieren, dass die
typischen „läuft in Debug, bricht in Release"-Bugs **gar nicht erst entstehen**.

> **Versions-Anker (live 2026-06-03):** BestJournalAndroid (Play-Store-App) = **AGP 8.7.3 / R8 8.7.x**,
> EntropieReductor (private App) = **AGP 8.10.0 / R8 8.10.x**, plus AGP-9.0/9.2-Ausblick. R8 ist in
> allen 4 Android-Projekten aktiv (`isMinifyEnabled = true` + `isShrinkResources = true` im Release).

> **Quellen-Rangordnung:** offizielle Google/Android/Firebase-Doku = Grundwahrheit; Blogs = `(extern)`.

## A — Inkrementell einführen + Verifikations-Workflow (offiziell)

- **R8 NIE komplett abschalten.** `minifyEnabled false` ist kein Fix, sondern Funktionsverlust
  (größeres/langsameres APK, kein Obfuscation-Schutz). Stattdessen Root-Cause (fehlende keep-Regel) fixen.
  [Enable app optimization](https://developer.android.com/topic/performance/app-optimization/enable-app-optimization) (offiziell)
- **Schrittweise aktivieren** (Google „Adopt optimizations incrementally"): erst nur Shrinking
  (temporär `-dontobfuscate` + `-dontoptimize`), dann Obfuscation (`-dontobfuscate` entfernen), dann
  Optimization (`-dontoptimize` entfernen) — nach JEDEM Schritt Release auf echtem Gerät testen.
  Optional zuerst Compat-Mode (`android.enableR8.fullMode=false`), dann Full-Mode aktivieren.
  [Adopt optimizations incrementally](https://developer.android.com/topic/performance/app-optimization/adopt-optimizations-incrementally) (offiziell)
- **Scope eingrenzen statt aufgeben:** Bricht ein Teil, temporär eine paket-breite Regel setzen, dann
  schrittweise durch **gezielte** keep-Regeln ersetzen — nie als Dauerlösung stehen lassen.
- **Debug-vs-Release-Falle:** Ein grüner Debug-Build sagt nichts über Tree-Shaking, Inlining,
  Class-Merging oder Obfuscation. **Immer einen minified, „release-like" Build testen** — empfohlen ein
  eigener, debugbarer Test-Buildtype, der die Release-Optimierung 1:1 erbt:
  ```kotlin
  buildTypes {
      release {
          isMinifyEnabled = true
          isShrinkResources = true
          proguardFiles(getDefaultProguardFile("proguard-android-optimize.txt"), "proguard-rules.pro")
      }
      create("releaseTest") {
          initWith(buildTypes.getByName("release"))  // identische keep-Regeln + R8-Verhalten
          isDebuggable = true                        // aber debugbar → reproduzierbarer R8-Test
      }
  }
  ```
  So findet man R8-Brüche reproduzierbar VOR dem Upload, ohne Drift zum echten Release.
  [Enable app optimization](https://developer.android.com/topic/performance/app-optimization/enable-app-optimization) (offiziell)
- **R8-Output-Dateien PRÄVENTIV lesen** (`app/build/outputs/mapping/<variant>/`), nicht erst nach einem
  Crash: `missing_rules.txt` (von R8 vorgeschlagene fehlende Regeln — bewusst abarbeiten, nicht blind
  hineinkopieren), `usage.txt` (was R8 ENTFERNT hat), `seeds.txt` (was behalten/nicht obfuskiert wurde —
  zeigt zu breite Regeln), `resources.txt` (Resource-Shrinking). `-printconfiguration` für die gemergten
  Regeln (auch aus Libs), `-whyareyoukeeping class X` für die Referenzkette einer behaltenen Klasse.
  [Configure and troubleshoot R8 keep rules](https://android-developers.googleblog.com/2025/11/configure-and-troubleshoot-r8-keep-rules.html) (offiziell)
- **R8 Configuration Analyzer (neu, proaktivstes Werkzeug):** ab R8 9.3.7-dev / AGP 9.3.0-alpha05 erzeugt
  `assembleRelease` automatisch `configanalyzer.html` mit Shrinking-/Optimization-/Obfuscation-Score und
  flaggt **überbreite, subsumierte, ungenutzte, identische** keep-Regeln sowie schädliche Library-Regeln —
  **ohne dass ein Crash nötig ist**. Ältere AGP:
  `-Dcom.android.tools.r8.dumpkeepradiushtmltodirectory=/tmp/r8analysis`.
  [R8 Configuration Analyzer](https://developer.android.com/topic/performance/app-optimization/r8-configuration-analyzer) (offiziell)

## B — Vor dem Upload verifizieren: Play-Store-Sicherheitsnetze (offiziell)

- **Smoke-Test-Matrix auf echtem Gerät** mit dem minified (release/releaseTest-)Build: jeden Hauptpfad
  einmal durchklicken. Gezielt die **Reflection-/Serialisierungs-Pfade** prüfen — genau dort schlägt R8
  zu (JSON-(De)Serialisierung, dynamisches Klassenladen, Enum-by-name, Plugin-Systeme, JNI).
- **Internen/geschlossenen Test-Track als R8-Verifikationsstufe** nutzen: Release-Build (R8 aktiv) zuerst
  auf internen, dann geschlossenen Track, dann **staged Production-Rollout** (z.B. 1 %/5 %/…). So bleiben
  R8-Optimierungs-Crashes auf wenige Nutzer begrenzt, bevor 100 % erreicht werden.
- **Pre-Launch-Report** (Play Console): wird automatisch erzeugt, sobald ein AAB auf einen Test-Track
  hochgeladen wird. Läuft auf einer breiten Geräte-Matrix, crawlt die App per Robo-Test und findet
  Crashes/ANRs/defekte Libs/unsupported APIs — **ein Test des bereits minifizierten Release-Artefakts**,
  also ideales R8-Sicherheitsnetz (kein Ersatz für eigene QA).
  [Pre-launch reports](https://support.google.com/googleplay/android-developer/answer/9844487) (offiziell)
- **Firebase Test Lab Robo-Test vertiefen:** eigene Robo-Scripts für kritische User-Journeys (Login,
  Kauf, Sync) hinterlegen, längere Laufzeiten + Ziel-Geräte/Locales — tiefere Abdeckung als der
  Standard-Pre-Launch-Report.
  [Run a Robo test](https://firebase.google.com/docs/test-lab/android/robo-ux-test) (offiziell)

## C — Reflection/Serialisierung: consumer-rules zuerst, Codegen statt Reflection

> Die häufigste Crash-Klasse. Grundregel: **aktuelle Lib-Versionen** (bringen Full-Mode-consumer-rules
> mit) + **Codegen statt Reflection** + eigene Modelle annotations-gesteuert halten. Bug-Details:
> `bugs/android-build/r8.md` Abschnitt C/D/F.

- **Mindestversionen mit gebündelten Full-Mode-Regeln:** Gson **2.11.0+**, Retrofit **2.9.0+**,
  kotlinx.serialization **1.6.0+**, Moshi (codegen), Room, WorkManager, OkHttp aktuell. consumer-rules
  decken nur Lib-Internas ab — **eigene Modellklassen muss man selbst halten**.
  [shrink-code](https://developer.android.com/build/shrink-code) (offiziell)
- **Codegen statt Reflection bevorzugen** (vermeidet die fragilsten keep-Regeln komplett):
  kotlinx.serialization (Compiler-Plugin, kein Laufzeit-Reflection), Moshi-codegen
  `@JsonClass(generateAdapter = true)` statt `KotlinJsonAdapterFactory`, **KSP statt kapt** (kapt deprecated).
  [moshi README](https://github.com/square/moshi/blob/master/README.md) (offiziell)
- **Pro-Lib release-feste Konfiguration** (funktionserhaltend, eng):
  - **Gson:** `@SerializedName` auf JEDES serialisierte Feld (macht Feldnamen obfuskierungs-immun) +
    `-keepattributes Signature` für generische `TypeToken`. Ohne `@SerializedName` liefert Gson im
    Full-Mode **still** leere/falsche Werte (kein Crash!).
  - **kotlinx.serialization:** Plugin nutzen; für Enums (Full-Mode) und **named companion** zusätzlich
    `-keepattributes InnerClasses` + `$$serializer`-keep (Default-Regeln greifen dort nicht).
  - **Room:** über KSP — generiert Impl + bringt eigene consumer-rules, keine Modell-keeps nötig.
  - **Retrofit + OkHttp:** aktuelle Versionen (consumer-rules im Artefakt); Response-Modelle möglichst
    über kotlinx.serialization/Moshi-codegen statt reflective Gson.
  - **Hilt `@HiltViewModel`** (Bug aktuell OPEN, [dagger#4739](https://github.com/google/dagger/issues/4739)):
    keep-Regel manuell setzen —
    `-keep,allowobfuscation @dagger.hilt.android.lifecycle.HiltViewModel class * extends androidx.lifecycle.ViewModel { <init>(...); }`.
  - **Firebase Firestore-Modelle:** `@Keep` + expliziter No-Arg-Konstruktor + Setter pro Property
    (`toObject()` braucht den No-Arg-Ctor, den Full-Mode nicht implizit behält). `@PropertyName`/`@DocumentId`
    für erhaltene Namen.
  - **Compose type-safe Navigation mit Enum-Args:** Enum-Klasse `@Keep` (R8 Full-Mode erzeugt sonst
    separate Serializer-Instanzen → Release-Crash). Navigation **2.8.3** hat dafür einen Lint-Check.
- **Eigene Modelle, sauberste Strategie:** annotations-gesteuert serialisieren (`@Serializable` /
  `@JsonClass`) → Codegen, keine Modell-keeps; `@Keep` **nur punktuell** wo eine Lib Reflection braucht;
  Wire-Feldnamen explizit annotieren (`@SerializedName`/`@SerialName`/`@PropertyName`) → entkoppelt
  Wire-Format von der Obfuskierung. **Niemals** pauschal `-keep class com.app.model.** { *; }`.
- **Zu meidende Kombinationen:** Kotlin `no-arg`-Plugin + Firebase (inkompatibel — manueller No-Arg-Ctor +
  `@Keep`); reflective Moshi (`KotlinJsonAdapterFactory`) in Release-Apps; reflective Gson für neue Modelle.
  ([discuss.kotlinlang.org](https://discuss.kotlinlang.org/t/no-arg-compiler-plugin-incompatible-with-firebase-in-andorid/7775) (extern))

## D — keep-Regeln richtig schreiben (eng vor breit)

> Leitprinzip (offiziell): keep-Regeln so ENG wie möglich, damit R8 maximalen Optimierungs-Spielraum
> behält. Jede unnötig breite Regel kostet App-Größe + Performance. Anti-Pattern-Bug-Details:
> `bugs/android-build/r8.md` Abschnitt I.

- **Richtigen Modifier wählen:**
  - `-keep` — hält Klasse + Member (kein Entfernen/Umbenennen). Nur für echte dynamische Entry-Points;
    schaltet Optimierung für die Klasse weitgehend ab — sparsam.
  - `-keepclassmembers` — **bevorzugter Default:** hält Member nur, falls die Klasse ohnehin überlebt;
    Klasse selbst darf R8 entfernen/optimieren.
  - `-keepclasseswithmembers` — Klasse + Member nur, wenn ALLE genannten Member existieren (konditional).
  - `-keepnames`/`-keepclassmembernames` **vermeiden** — stattdessen explizit `-keep,allowshrinking …`.
  [add-keep-rules](https://developer.android.com/topic/performance/app-optimization/add-keep-rules) (offiziell)
- **Modifier zum Aufweichen breiter Regeln (R8 Spielraum zurückgeben):** `allowshrinking` (darf entfernen
  wenn ungenutzt), `allowobfuscation` (darf umbenennen), `allowoptimization` (darf inlinen),
  `allowaccessmodification`, `includedescriptorclasses` (JNI). An jede sonst harte `-keep`-Regel anhängen,
  wo nur die Existenz (nicht der Name) gebraucht wird.
- **Conditional keeps mit `-if` + Backreferences `<1>`, `<2>`** — präzise statt Wildcard-Holzhammer:
  ```proguard
  # nur Klassen MIT @SerializedName-Feldern halten — nicht pauschal das ganze Modell-Package
  -if class ** { @com.google.gson.annotations.SerializedName <fields>; }
  -keep class <1> { @com.google.gson.annotations.SerializedName <fields>; <init>(...); }
  ```
  **Falle:** Backreferences brechen, wenn Klassen- UND Membername gewildcarded sind, bzw. bei negierten
  Wildcard-Namen in der Konsequenz.
- **`@androidx.annotation.Keep` vs `proguard-rules.pro`:** `@Keep` blockt Shrinking + Obfuscation in
  EINEM Schritt (keine granulare Steuerung, kein `allowobfuscation`) — gut für punktuelle „nicht
  anfassen"-Fälle nahe am Code. `proguard-rules.pro` für präzise Kontrolle (Modifier, `-if`, member-genau).
  Neuere, präzisere Alternative: R8 **keep-annotations** (`@UsesReflection`/`@KeepTarget`, wandert in androidx).
- **`-keepattributes` — nur was nötig** (jedes Attribut bremst globale Optimierung): `Signature`
  (generische Reflection), `RuntimeVisibleAnnotations` (Annotationen zur Laufzeit lesen), `InnerClasses`/
  `EnclosingMethod` (`getDeclaredClasses`), `SourceFile`+`LineNumberTable` (lesbare Stacktraces).
  **Full-Mode-Hinweis:** `-keepattributes Signature` allein wirkt nicht — der zugehörige Code muss
  ebenfalls von einer keep-Regel gematcht sein.
- **Anti-Patterns → korrekte Alternative:**
  | Anti-Pattern | Problem | Richtig |
  |--------------|---------|---------|
  | `-keep class com.app.** { *; }` | schaltet R8 fürs ganze Paket ab | Member-Level / `-keepclassmembers` + `-if`/Annotation-Selektor |
  | `-keep class !com.app.foo.** { *; }` | Negation invertiert → behält ALLES außer foo | positive, präzise Regeln |
  | manuelle keep für Activities/Services/Receiver | redundant (in `proguard-android-optimize.txt`) | weglassen |
  | globales `-ignorewarnings` | verschluckt echte Missing-Class-Fehler | gezielt `-dontwarn com.lib.**` aus `missing_rules.txt` |
  | `proguard-android.txt` als Default | aktiviert keine Optimierung, entfällt ab AGP 9.0 | immer `proguard-android-optimize.txt` |
  [Configure and troubleshoot R8 keep rules](https://android-developers.googleblog.com/2025/11/configure-and-troubleshoot-r8-keep-rules.html) (offiziell)
- **Wo platzieren:** App-Reflection-Regeln in `proguard-rules.pro`; Library-Regeln eng gescoped per
  `consumerProguardFiles` in den AAR. Immer beim zugehörigen Code halten.

## E — Full-Mode sicher MAXIMIEREN + Logging/Optimierung steuern

> Full-Mode (Default seit AGP 8.0) ist die Wurzel der meisten „Debug ok, Release bricht"-Bugs — aber auch
> der größte Performance-Hebel. Nicht abschalten, sondern die wenigen keep-Regeln präzise setzen.
> Bug-Details: `bugs/android-build/r8.md` Abschnitt A + H.

- **Was Full-Mode bringt (belegte Praxiszahlen):** Reddit nach R8-Optimierung *40 % schnellerer
  Cold-Start, 30 % weniger ANRs, 25 % bessere Frame-Renderung, 14 % kleiner*; Disney+ nach Wechsel von
  `proguard-android.txt` auf `proguard-android-optimize.txt` *30 % schnellerer Start, 25 % weniger ANRs*.
  [Use R8 to shrink, optimize…](https://android-developers.googleblog.com/2025/11/use-r8-to-shrink-optimize-and-fast.html) (offiziell)
- **`android.enableR8.fullMode=false` NUR zum Eingrenzen** eines Verdachts — danach sofort wieder
  entfernen (Zeile löschen = Full-Mode).
  [full-mode](https://developer.android.com/topic/performance/app-optimization/full-mode) (offiziell)
- **Die 6 Full-Mode-Verschärfungen funktionserhaltend gegensteuern** (jeweils MINIMAL keepen, kein
  `{ *; }`-Holzhammer): (1) Attribute nur bei explizitem keep → `-keepattributes Signature` + Klasse
  keepen; (2) kein impliziter No-Args-Ctor → `-keep class X { <init>(); }`; (3) `-allowaccessmodification`
  by default an (private→public fürs Inlining) → Member + Sichtbarkeit explizit halten, falls per
  Reflection genutzt; (4) Interface-Default-Methoden nicht implizit; (5) Relationship-Attribute nur wenn
  BEIDE Endpunkte gekeept; (6) `SourceFile` wird umgeschrieben → `-renamesourcefileattribute SourceFile`
  + `-keepattributes SourceFile,LineNumberTable` + mapping.txt-Upload.
  [compatibility-faq](https://r8.googlesource.com/r8/+/refs/heads/main/compatibility-faq.md) (offiziell)
- **`-assumenosideeffects` RICHTIG (Log-Calls entfernen):** nur mit **exakten Methoden-Signaturen**:
  ```proguard
  -assumenosideeffects class android.util.Log {
      public static int v(java.lang.String, java.lang.String);
      public static int d(java.lang.String, java.lang.String);
      public static int i(java.lang.String, java.lang.String);
      public static int w(java.lang.String, java.lang.String);
      public static int e(java.lang.String, java.lang.String);
  }
  ```
  **GEFÄHRLICH:** `-assumenosideeffects class android.util.Log { *; }` matcht die Hierarchie bis
  `java.lang.Object` hoch → R8 darf `wait/notify/synchronized` als seiteneffektfrei wegoptimieren →
  Races/Deadlocks NUR im Release. **NIE `*`-Wildcard.** `-assumevalues` ≠ `-assumenosideeffects` (ersteres
  entfernt den Call nicht).
  [Jake Wharton — Value Assumption](https://jakewharton.com/r8-optimization-value-assumption/) (extern),
  [Yazio — break your app with R8](https://medium.com/yazio-engineering/how-to-break-your-android-app-with-proguard-r8-6566bc387b63) (extern)
- **`proguard-android-optimize.txt` als Default** (nicht `proguard-android.txt`, enthält `-dontoptimize`,
  entfällt AGP 9.0). `-optimizations` wird von R8 ignoriert, `-optimizationpasses` erzeugt nur eine
  Warnung — aus Alt-Configs entfernen.

## F — Resource-Shrinking absichern

> Bug-Details: `bugs/android-build/r8.md` Abschnitt G.

- `isShrinkResources = true` immer **zusammen mit** `isMinifyEnabled = true` (sonst Build-Fehler/ignoriert).
- Dynamisch (per `getIdentifier()`) geladene Ressourcen in `res/raw/<package>.keep.xml` mit `tools:keep` +
  gesetztem `xmlns:tools`-Namespace sichern (sonst wirkungslos).
- `safe`-Modus (Default) beibehalten; `strict` nur mit vollständiger `tools:keep`-Liste.
- `resConfigs`/`resourceConfigurations` nur setzen, wenn ALLE unterstützten Locales gelistet sind (sonst
  werden Übersetzungen weggeworfen — Falle bei i18n-Apps).
- Vor AGP-9.0-Upgrade (automatisches `optimizedResourceShrinking`, ab 8.12 opt-in) Release gründlich
  testen — dynamisch geladene Ressourcen werden aggressiver entfernt.
  [Customize which resources to keep](https://developer.android.com/topic/performance/app-optimization/customize-which-resources-to-keep) (offiziell)

## G — Deobfuskation & Crash-Reporting für den Play Store

> Bug-Details: `bugs/android-build/r8.md` Abschnitt N + F4.

- **mapping.txt ist im AAB automatisch enthalten** (AGP 4.1+, R8 aktiv) und wird beim Upload mit der
  Version assoziiert — Android Vitals deobfuskiert Crashes/ANRs per ReTrace. **KRITISCHES TIMING:** nur
  Crashes NACH dem Mapping-Upload werden deobfuskiert → Mapping muss im AAB sein, nicht nachträglich.
  Manueller Nachweg falls nötig: Play Console → Test and release → App bundle explorer → Downloads →
  Assets → „Add ReTrace mapping file".
  [Deobfuscate crash stack traces](https://support.google.com/googleplay/android-developer/answer/9848633) (offiziell)
- **`-keepattributes SourceFile,LineNumberTable`** setzen — sonst fehlen Dateinamen/Zeilen in Vitals UND
  Crashlytics.
- **Native Debug Symbols (NDK)** getrennt vom R8-Mapping: `android.buildTypes.release.ndk.debugSymbolLevel
  = "SYMBOL_TABLE"` (oder `"FULL"`). Automatisch im AAB ab AGP 4.1+. **Größenlimit ~300 MB** → bei
  Überschreitung `SYMBOL_TABLE` statt `FULL`.
  [Native debug symbols](https://developer.android.com/build/include-native-symbols) (offiziell)
- **Firebase Crashlytics:** Gradle-Plugin **v3.0.0+** ist Pflicht ab AGP 8.1+ (lädt Mapping automatisch
  hoch; ältere inkompatibel). Mindestens google-services-Plugin 4.4.1+. Achtung beim v3-Upgrade: die
  entfernten Gradle-Felder `mappingFile`/`strippedNativeLibsDir`/`symbolGenerator`-Closure brechen sonst
  den Build (siehe `bugs/android-build/r8.md` F4).
  [Get deobfuscated reports](https://firebase.google.com/docs/crashlytics/android/get-deobfuscated-reports) (offiziell)
- **mapping.txt pro veröffentlichter Version archivieren** (z.B. `$HOME/SK/<projekt>/mappings/<versionCode>/`,
  außerhalb des Repos) — die Datei wird bei jedem Build überschrieben. Eigene Stacktraces:
  `retrace mapping.txt stacktrace.txt` (`--verbose` für Parameter/Return-Typen).
  [R8 retrace](https://developer.android.com/tools/retrace) (offiziell)
- **class/method-merging → mehrdeutiges retrace:** ein obfuskierter Frame kann auf mehrere Original-
  Methoden mappen; `# com.android.tools.r8.synthesized`-Annotationen in mapping.txt helfen. Bei kritischem
  Bedarf an eindeutigen Stacks gezielt `-keep`/`-keepclassmembers` (funktionserhaltend, nur weniger
  aggressiv). (extern)

## H — Startup-Performance: Baseline & Startup Profiles mit R8

> R8 und Baseline Profiles sind **orthogonal und ergänzend** — R8 schrumpft/optimiert, das Profil
> beschleunigt den Start heißer Pfade (~30 %). R8 NIE „wegen Baseline Profile" abschalten. Bug-Details für
> die Fallen: siehe „GEFUNDENE BUGS" unten / `bugs/android-build/r8.md` (Performance-Querverweis).

- **R8 erweitert das Profil (ab AGP 8.2):** R8 schreibt die unobfuskierten Profilregeln auf den
  obfuskierten Release-Code um → +~30 % Methodenabdeckung. Ohne R8 verliert man diese Erweiterung.
  [Baseline Profiles overview](https://developer.android.com/topic/performance/baselineprofiles/overview) (offiziell)
- **Zentrale Regel:** Profil GEGEN den **unobfuskierten** Build generieren (`isMinifyEnabled = false`; das
  `androidx.baselineprofile`-Plugin setzt zusätzlich `-dontobfuscate`/`-dontoptimize`), ANWENDEN auf den
  minified Release — die Toolchain mappt automatisch. **Veraltetes Profil** (nach Rename/Refactoring) lässt
  das Mapping ins Leere laufen → Start wird **still** langsamer, kein Fehler → **bei jedem Release neu
  generieren + in CI verankern**.
- **Setup:** eigenes `com.android.test`-Modul + `androidx.baselineprofile`-Plugin
  (`targetProjectPath = ":app"`), Macrobenchmark-Generator-Test (`BaselineProfileRule`, CUJs abdecken,
  `includeInStartupProfile = true`), `androidx.profileinstaller`-Dependency, Generierung via
  `./gradlew :app:generateBaselineProfile` (gerootetes Device/Emulator oder API 33+ mit Macrobenchmark 1.2+).
  [Create a Baseline Profile](https://developer.android.com/topic/performance/baselineprofiles/create-baselineprofile) (offiziell)
- **AAB-Einbettung:** binäres Profil landet in `assets/dexopt/baseline.prof`, **muss < 1,5 MB** sein (sonst
  ohne Build-Fehler nicht eingepackt). Play verteilt das Baseline Profile sofort beim Install;
  **Cloud/Aggregated Profiles** (ab API 28) ergänzen es über Stunden/Tage aus realem Nutzerverhalten.
- **Startup Profile (`startup-prof.txt`) + DEX-Layout:** lässt R8/D8 startkritische Klassen in die ersten
  DEX-Files legen (+15–30 % Startgewinn). `dexLayoutOptimization` ist ab AGP 8.3 default an (8.1–8.2
  manuell), **R8 muss aktiv sein**. Startkritischen Code in `classes.dex` halten.
  [DEX layout optimizations](https://developer.android.com/topic/performance/baselineprofiles/dex-layout-optimizations) (offiziell)
- **Verifikation:** Macrobenchmark `CompilationMode.None` vs. `DEFAULT`/`Partial(Require)` auf einem
  non-debuggable, minified `benchmark`-Buildtype (`initWith(release)` + debug-signing). Android 14+ hält den
  Compile-State zwischen Iterationen; darunter `CompilationMode.Ignore`.
  [Macrobenchmark](https://developer.android.com/topic/performance/benchmarking/macrobenchmark-overview) (offiziell)

## I — Versions-Hygiene, R8-Override & CI-Gate

> Bug-Details: `bugs/android-build/r8.md` Abschnitt J (Versions-Bugs) + O (Fix-Status) + M (Upgrade-Breaking).

- **AGP-Patch-Versionen aktuell halten** — viele R8-Miscompilation-Bugs werden in Patch-Releases gefixt.
  **Konkret kritisch für die Play-Store-App (AGP 8.7.3):** die SPI/ServiceLoader-Regression **#389737060**
  betrifft R8 in 8.6.*/8.7.*/8.8.0 und ist erst in **AGP 8.9.1** gefixt → bei `ServiceLoader`/
  `META-INF/services`-Nutzung (oft transitiv) auf ≥ 8.9.1 heben.
  [AGP 8.9.0 Release Notes](https://developer.android.com/build/releases/agp-8-9-0-release-notes) (offiziell)
- **R8 unabhängig von AGP aktualisieren** (für einen bestätigten R8-Bugfix ohne AGP-Upgrade) — Override in
  der top-level `settings.gradle(.kts)`:
  ```kotlin
  pluginManagement {
      buildscript {
          repositories { mavenCentral(); maven { url = uri("https://storage.googleapis.com/r8-releases/raw") } }
          dependencies { classpath("com.android.tools:r8:<version>") }
      }
  }
  ```
  Nur bewusst + gepinnt + mit grünem Release-Build im CI; nie dauerhaft „latest" (Inkompatibilitäts-Risiko).
  [r8.googlesource.com/r8](https://r8.googlesource.com/r8) (offiziell)
- **CI-Release-Gate:** im CI den **minified Release-Build** bauen (`bundleRelease`/`assembleRelease`),
  nicht nur Debug — R8-Fehler werden in Debug nie sichtbar. Smoke-/Instrumented-Tests gegen den minified
  Build. (extern, breit belegt)
- **Reproduzierbarkeit:** AGP/R8/Kotlin/Lib-Versionen im Version-Catalog (`gradle/libs.versions.toml`)
  pinnen, Gradle-Wrapper pinnen (`distributionSha256Sum`), deterministische (enge) keep-Regeln, mapping.txt
  pro Release archivieren.
  [build/dependencies](https://developer.android.com/build/dependencies) (offiziell)
- **R8-Build-Stabilität:** OOM in `minifyReleaseWithR8` → `org.gradle.jvmargs=-Xmx4096m` (oder mehr) in
  `gradle.properties`; zu breite keep-Regeln vermeiden (verhindern Optimierung + blähen Heap auf).
- **AGP-9.0-Vorbereitung (R8-relevant):** `proguard-android.txt` entfällt (nur noch
  `proguard-android-optimize.txt`); `optimizedResourceShrinking` automatisch; `globalOptionsInConsumerRules
  .disallowed` default → Library-Publishing bricht bei globalen Opt-Flags in consumer-rules (`ignoreFrom`
  als Übergang); **`strictFullModeForKeepRules` default → `-keep class A` impliziert NICHT mehr `<init>()`**
  (explizit `-keep class A { <init>(); }`).
  [AGP 9.0 Release Notes](https://developer.android.com/build/releases/agp-9-0-0-release-notes) (offiziell)

## J — Pflicht-Checkliste vor jedem Play-Store-Release mit R8

```
□ Minified RELEASE-Build (release/releaseTest) auf echtem Gerät getestet — Debug beweist NICHTS.
□ Reflection-/Serialisierungs-Pfade gezielt durchgeklickt (Gson/Moshi/kotlinx/Firestore/Retrofit/Hilt).
□ missing_rules.txt geprüft + gezielt abgearbeitet; keine zu breiten -keep, keine Negation !.
□ (falls verfügbar) R8 Configuration Analyzer-Score geprüft — keine überbreiten Regeln.
□ -assumenosideeffects nur mit exakten Signaturen; proguard-android-optimize.txt als Default.
□ minifyEnabled UND shrinkResources beide true; dynamische Ressourcen in <package>.keep.xml; resConfigs i18n ok.
□ -keepattributes SourceFile,LineNumberTable gesetzt; mapping.txt im AAB; Crashlytics-Plugin v3+.
□ mapping.txt (+ native-debug-symbols.zip) für diese Version extern archiviert.
□ Baseline Profile frisch generiert (gegen unobfuskierten Build), < 1,5 MB, in CI verankert.
□ AGP-Patch aktuell: bei 8.7.3 + ServiceLoader → #389737060 betrifft dich (≥ 8.9.1 erwägen).
□ Upload zuerst auf internen/geschlossenen Track → Pre-Launch-Report grün → staged rollout (1/5/…%).
□ CI hat den minified Release gebaut + getestet (nicht nur Debug).
```
