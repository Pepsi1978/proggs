# R8 — Bug-Almanach (Android Code-Shrinker / Optimizer / Obfuscator)

> **PFLICHT VOR DER ARBEIT LESEN.** Bevor du an einer App R8 aktivierst/anfasst
> (`isMinifyEnabled`, `isShrinkResources`, `proguard-rules.pro`, `consumerProguardFiles`,
> Release-Build, AGP-Upgrade) — diesen Almanach komplett lesen. R8 macht Apps „von hinten
> kaputt": es läuft im **Debug perfekt** und crasht/verliert Funktionen **nur im Release**,
> weil R8 reflektiv genutzten Code entfernt oder umbenennt. Fast jeder Bug hier hat dieselbe
> Wurzel: **fehlende `keep`-Regel** für etwas, das nur per Reflection/Serialisierung/JNI
> erreicht wird.

**Stand:** recherchiert am **2026-06-03**, **re-recherchiert am 2026-07-02** (Engine A: Firecrawl+MiniMax)
für die live ermittelten Versionen:
- **AGP 8.7.3 → R8 8.7.x** — BestJournalAndroid (Play-Store-App), BestJournalFrank, NEMS
- **AGP 8.10.0 → R8 8.10.x** — EntropieReductor
- **R8 Full-Mode ist Default seit AGP 8.0** (`android.enableR8.fullMode=true`). Das ist der
  Schlüsselkontext: Full-Mode ist deutlich aggressiver als der alte ProGuard-/Compat-Mode.
- **Versions-Horizont (Re-Recherche 2026-07-02):** AGP **9.0.1** (Jan 2026) + **9.2.x** existieren
  mit weiteren R8-Änderungen (siehe §M); Frank bleibt bei 8.7.3/8.10.0 → das ist Zukunftswissen
  fürs AGP-9-Upgrade. Keine neuen Miscompilation-Bugs für 8.7.3/8.10.0 gefunden (Bestand aktuell).

**Ist-Zustand:** R8 ist in **allen 4 Android-Projekten aktiv** (`isMinifyEnabled = true` +
`isShrinkResources = true` im Release). BestJournalAndroid seit 2026-05-31 („PS-001 Release-Hardening").

## A — Grundmechanik: Full-Mode (Default seit AGP 8.0) macht 6 Dinge aggressiver

Full-Mode ist die Wurzel der meisten „läuft in Debug, bricht in Release"-Bugs. Quelle:
[Use R8 in full mode](https://developer.android.com/topic/performance/app-optimization/full-mode),
[R8 compatibility FAQ](https://r8.googlesource.com/r8/+/refs/heads/main/compatibility-faq.md).

| # | Was Full-Mode anders macht | Folge | Gegenmaßnahme (funktionserhaltend) |
|---|----------------------------|-------|-----------------------------------|
| A1 | Behält **Signature/Annotation/InnerClasses** NUR für explizit per `-keep` gematchte Klassen (Compat behielt pauschal) | Generics weg → Gson/Retrofit/Serialisierung bricht | `-keepattributes Signature` **plus** explizite `-keep` der Klasse |
| A2 | Behält den **No-Args-Konstruktor NICHT implizit**, auch wenn die Klasse gekeept ist | `newInstance()`/`getDeclaredConstructor()` → `NoSuchMethodException` | `-keep class X { <init>(); }` |
| A3 | Ändert **Sichtbarkeit** (private→public) fürs Inlining (`-allowaccessmodification` aktiv) | Reflection auf private Member bricht | Member mit Original-Visibility keepen; Lib-API: `-dontallow accessmodification` |
| A4 | Behält **Default-Methoden** von Interfaces nicht implizit | Interface-Default-Methode via Reflection weg | `-keep class X { <methods>; }` |
| A5 | Relationship-Attribute (InnerClasses/EnclosingMethod) nur wenn **beide** Endpunkte gekeept sind | `-keepattributes InnerClasses` wirkt scheinbar nicht | Beide verwandten Klassen explizit keepen |
| A6 | Schreibt **SourceFile** immer um | Stacktraces | `-renamesourcefileattribute SourceFile` |

**Notausstieg zum Eingrenzen (temporär, NICHT als Dauerlösung):**
`android.enableR8.fullMode=false` schaltet auf Compat-Mode zurück. Damit prüfen, ob ein Crash
Full-Mode-spezifisch ist — dann gezielte keep-Regel nachziehen und Full-Mode wieder anschalten.

## B — Diagnose-Workflow (IMMER zuerst, spart Stunden)

Release bauen, dann `app/build/outputs/mapping/release/` ansehen:

| Datei / Werkzeug | Zweck |
|------------------|-------|
| `missing_rules.txt` | R8 schlägt **fehlende keep-Regeln direkt vor** — Copy-Paste-Startpunkt |
| `usage.txt` | Was R8 **entfernt** hat — hier die „verschwundene" Klasse/Methode suchen |
| `seeds.txt` | Was gekeept wurde — prüfen ob die erwartete Klasse fehlt |
| `configuration.txt` / `-printconfiguration build/outputs/logs/configuration.txt` | **Alle gemergten Regeln** (auch aus Libs) — Quelle einer problematischen Regel finden |
| `resources.txt` | Resource-Shrinking: `reachable=true/false` pro Ressource zurückverfolgen |
| `mapping.txt` + `retrace` | Stacktraces **deobfuskieren**. `mapping.txt` pro Release SICHERN (wird beim Rebuild überschrieben!) |
| `-whyareyoukeeping class X` | Referenzkette, warum Code behalten wird (Compat; unter R8 eingeschränkt) |
| **R8 Configuration Analyzer** (`configanalyzer.html`) | Ab R8 9.3.7-dev / AGP 9.3.0-alpha05: erzeugt beim `assembleRelease` automatisch einen HTML-Report mit Shrinking-/Optimization-/Obfuscation-Score und flaggt **überbreite, subsumierte, ungenutzte, identische** keep-Regeln + schädliche Lib-Regeln — **ohne Crash, präventiv**. Ältere AGP: `-Dcom.android.tools.r8.dumpkeepradiushtmltodirectory=/tmp/r8analysis`. ([R8 Configuration Analyzer](https://developer.android.com/topic/performance/app-optimization/r8-configuration-analyzer)) |

## C — Reflection / Serialisierung: Library-keep-Regeln (die häufigste Crash-Klasse)

> Grundregel: **Offizielle consumer-rules / aktuelle Lib-Version zuerst.** Die Lib deckt aber
> NIE deine eigenen Modellklassen ab — die musst du selbst halten.

### C1. Gson — generische Typen / null-Felder ⭐ HÄUFIG
**Symptom:** Im Release wird ein deserialisiertes Modell `null` oder leer; `ClassCastException`,
`IllegalStateException`, oder `java.lang.Class cannot be cast to ParameterizedType`. Debug OK.
**Ursache:** (1) Full-Mode strippt das `Signature`-Attribut → Gson kann `List<Foo>` etc. nicht
auflösen. (2) R8 benennt Modell-Feldnamen um → JSON-Keys matchen nicht. (3) Full-Mode sieht die
nur per Reflection erzeugte Modellklasse als „nie instanziiert" → ersetzt sie durch `null`.
**Versionen:** alle Gson unter Full-Mode (AGP 8.0+). Gson **2.11.0+** bringt eigene Basis-Regeln mit.
**FIX:**
```proguard
-keepattributes Signature
-keep,allowobfuscation,allowshrinking,allowoptimization class com.google.gson.reflect.TypeToken
-keep,allowobfuscation,allowshrinking,allowoptimization class * extends com.google.gson.reflect.TypeToken
# Felder mit @SerializedName behalten (Obfuskation erlaubt — der Name kommt aus der Annotation):
-keepclassmembers,allowobfuscation class * { @com.google.gson.annotations.SerializedName <fields>; }
```
Ohne `@SerializedName`: eigene Modelle selbst halten (`-keep class my.model.** { <fields>; }`).
Doppelte JSON-Namen in einer Hierarchie → `IllegalArgumentException` (unbenutzte Felder `transient`).
**Quelle:** [gson#2658 (OPEN, gh-verifiziert)](https://github.com/google/gson/issues/2658),
[gson#2401](https://github.com/google/gson/issues/2401), R8 compatibility FAQ.

### C2. Retrofit + OkHttp — Service-Interface wird `null`
**Symptom:** Release-Crash beim `create()`/Aufruf des Service; `Unable to create call adapter`;
`suspend`-Funktionen brechen; generische Rückgabetypen (`Response<List<X>>`) verloren.
**Ursache:** Full-Mode ersetzt Interfaces ohne konkrete Implementierung durch `null` (Retrofit baut
sie zur Laufzeit per `Proxy`); Generic-Signaturen werden gestrippt; `Continuation<T>`-Typ geht verloren.
**Versionen:** **Retrofit < 2.9.0 liefert KEINE Full-Mode-Regeln** → manuell. Ab 2.9.0/2.9.1 in der
AAR gebündelt. OkHttp/Okio: meist nur `-dontwarn okhttp3.**` / `okio.**`.
**FIX:** Retrofit auf aktuelle Version updaten (bringt `retrofit2.pro` mit). Falls nötig manuell:
```proguard
-keepattributes Signature
-keep,allowobfuscation,allowshrinking class kotlin.coroutines.Continuation
-if interface * { @retrofit2.http.* <methods>; }
-keep,allowobfuscation interface <1>
```
**Quelle:** [retrofit#3005 (CLOSED/COMPLETED, gh-verifiziert)](https://github.com/square/retrofit/issues/3005),
[retrofit#3880](https://github.com/square/retrofit/issues/3880), [retrofit#3751](https://github.com/square/retrofit/issues/3751).

### C3. kotlinx.serialization — Serializer nicht gefunden / named companion ⭐ HÄUFIG
**Symptom:** `SerializationException: Serializer for class 'X' is not found` trotz `@Serializable`;
bei serialisierbaren **Enums** im Full-Mode `ExceptionInInitializerError`; `NoSuchFieldError: Companion`.
**Ursache:** R8 obfuskiert/entfernt die `@Serializable`-Klasse, ihr `INSTANCE`-Feld oder die generierte
`serializer()`-Funktion. Bei **benanntem Companion** strippt Full-Mode das `InnerClasses`-Attribut,
das `getDeclaredClasses` braucht.
**Versionen:** Consumer-ProGuard-Regeln werden **seit 1.5.0-RC** mit `kotlinx-serialization-core-jvm` mitgeliefert
(aktuell **1.11.0**, Regeldatei [`rules/common.pro`](https://github.com/Kotlin/kotlinx.serialization/blob/master/rules/common.pro));
sie halten Serializer für alle nach dem Shrinking verbliebenen `@Serializable`-Klassen. **Manuell bleibt nötig** bei:
**named companion objects**, **Reflection-Tools** (z. B. Retrofit-Bodies) und **generisch verwendeten, nie direkt
referenzierten** Klassen (z. B. nur `List<MyType>.size`). < 1.5.0-RC zwingend komplett manuell.
**FIX:**
```proguard
-keepattributes InnerClasses
-keep @kotlinx.serialization.Serializable class *
-if @kotlinx.serialization.Serializable class **
-keepclassmembers,allowshrinking,allowobfuscation class <1> { *** Companion; }
-keepclasseswithmembers,allowshrinking,allowobfuscation class **$$serializer { *** INSTANCE; }
```
**Quelle:** [kotlinx.serialization#2501 (CLOSED/COMPLETED, gh-verifiziert)](https://github.com/Kotlin/kotlinx.serialization/issues/2501),
[#1129](https://github.com/Kotlin/kotlinx.serialization/issues/1129), [#2301](https://github.com/Kotlin/kotlinx.serialization/issues/2301).

### C4. Moshi — reflective vs codegen (wichtige Unterscheidung)
**Symptom:** Mit `KotlinJsonAdapterFactory` (reflective): `JsonDataException`/null-Felder. Mit codegen: meist OK.
**Ursache:** Reflective Moshi liest Properties über `kotlin.Metadata` → R8 strippt Metadata/obfuskiert Modelle.
Codegen (`@JsonClass(generateAdapter = true)`) erzeugt `*_JsonAdapter` zur Compile-Zeit → keine Reflection.
**FIX:** **Auf codegen umstellen** (empfohlen — keine fragilen keep-Regeln, keine `kotlin-reflect`-Dependency).
Bei reflective: `-keep class kotlin.Metadata { *; }` + Modelle/`<init>` halten.
**Quelle:** [moshi README](https://github.com/square/moshi/blob/master/README.md), [moshi#1818](https://github.com/square/moshi/issues/1818).

### C5. Jackson (jackson-databind) — reflection-lastig
**Symptom:** `InvalidDefinitionException`/`UnrecognizedPropertyException`; **Java Records brechen komplett**.
**Ursache:** Jackson nutzt Reflection (Creators, Getter/Setter, `@JsonProperty`); R8 obfuskiert Property-Namen
und entfernt no-arg-Ctors. Bekannter R8-Record-Bug.
**FIX:**
```proguard
-keepattributes *Annotation*,Signature
-keepclassmembers class my.model.** { <init>(...); <fields>; }
-dontwarn com.fasterxml.jackson.databind.**
```
Für Android meist Moshi/kotlinx.serialization die bessere Wahl.
**Quelle:** [jackson-databind#5192 „Record types are broken on Android when using R8" (CLOSED/COMPLETED, gh-verifiziert)](https://github.com/FasterXML/jackson-databind/issues/5192).

### C6. Room — Entities / Database
**Symptom:** `Cannot find implementation for ...Database`; fehlende Spalten.
**Ursache:** Room generiert `*_Impl`-Klassen; Entities werden über Annotationen/Reflection verarbeitet.
**FIX (ergänzend — Room bündelt eigene consumer-rules):**
```proguard
-keep class * extends androidx.room.RoomDatabase { <init>(); }
-keep @androidx.room.Entity class * { *; }
-dontwarn androidx.room.paging.**
```

## D — Kotlin-Sprache

### D1. Enum: `values()` / `valueOf()` / Konstanten-Namen ⭐ HÄUFIG
**Symptom:** Release-Crash `NoSuchMethodError`/`NoSuchFieldException`/`IllegalArgumentException` bei
`enumValueOf`/`valueOf("X")`; besonders Kotlin-Enums + Gson/Serialisierung.
**Ursache:** R8 entfernt die synthetischen `values()`/`valueOf()` und obfuskiert die Konstanten-**Namen**,
die per Reflection gebraucht werden.
**FIX:**
```proguard
-keepclassmembers,allowoptimization enum * {
    public static **[] values();
    public static ** valueOf(java.lang.String);
}
```
Wenn die Konstanten-Namen selbst reflektiert/serialisiert werden: betroffene Enums per `@Keep` oder
ohne `allowobfuscation` halten.
**Quelle:** [issuetracker #259389417](https://issuetracker.google.com/issues/259389417) (Status laut Quelle, unverifiziert),
[gson#1776](https://github.com/google/gson/issues/1776).

### D2. `kotlin.Metadata` gestrippt
**Symptom:** Kotlin-Reflection / Libs die `kotlin.Metadata` lesen (Moshi-reflective, kotlin-reflect) brechen.
**FIX:** `-keep class kotlin.Metadata { *; }` — **nur** wenn Reflection wirklich genutzt wird (kostet Größe).
**Wichtig:** data classes / sealed classes brauchen **keine** generelle keep-Regel — nur wenn sie
serialisiert/reflektiert werden (dann über die Gson/Moshi/kotlinx-Regeln oben).
**Quelle:** [JetBrains KT-72888](https://youtrack.jetbrains.com/issue/KT-72888) (Status laut Quelle, unverifiziert).

## E — Android-Mechanik (per Name/Reflection vom Framework gerufen)

### E1. Parcelable — `CREATOR`-Feld entfernt
**Symptom:** `BadParcelableException`/`no Parcelable.Creator` beim Lesen aus Parcel/Intent. Debug OK.
**Ursache:** R8 entfernt das statische `CREATOR`-Feld (nur per Reflection vom Framework gelesen).
**FIX:** `proguard-android-optimize.txt` enthält die Regel bereits — meist NICHT selbst nötig. Bei
Custom-Setup / Code-Gen-Parcelables:
```proguard
-keepclassmembers class * implements android.os.Parcelable { public static final ** CREATOR; }
```
`@Parcelize` (kotlin-parcelize) generiert `CREATOR` korrekt → abgedeckt.
**Quelle:** [parceler#138](https://github.com/johncarl81/parceler/issues/138).

### E2. JNI / native methods — `UnsatisfiedLinkError`
**Ursache:** Nativer Code ruft Java per festem Namen; R8 obfuskiert die Namen.
**FIX:**
```proguard
-keepclasseswithmembernames,includedescriptorclasses class * { native <methods>; }
-keepclassmembers class my.jni.Bridge { <methods>; }   # von C/C++ per Name gerufene Java-Methoden
```

### E3. WebView `@JavascriptInterface` obfuskiert → JS-Bridge bricht
**FIX:** `-keepclassmembers class * { @android.webkit.JavascriptInterface <methods>; }`

### E4. `Class.forName(variable)` / `getSimpleName()` als Programmlogik
**Symptom:** `ClassNotFoundException` bei dynamischem Klassennamen; Logik auf Klassennamen-Strings bricht.
**Ursache:** R8 löst nur String-**Literale** in `Class.forName("Lit")` auf, keine Variablen. Nach
Obfuskation sind Namen umbenannt; anonyme Klassen liefern leere Namen.
**FIX:** Schmale `-keep`-Regel für die betroffenen Klassen; **nie** auf `getSimpleName()`/`getCanonicalName()`
für Programmlogik verlassen — explizite Konstanten/`@Keep` nutzen.
**Quelle:** [Jake Wharton — Class Constant Operations](https://jakewharton.com/r8-optimization-class-constant-operations/).

## F — Frameworks / Dependency-Injection

### F1. Hilt/Dagger — `@HiltViewModel`-Konstruktor gestrippt ⭐ (NOCH OFFEN)
**Symptom:** Release-Crash `NoSuchMethodException` beim Erstellen eines `@HiltViewModel`; Debug OK.
**Ursache:** Commit [`0786d0a`](https://github.com/google/dagger/commit/0786d0af598028098849cb88a16b72549f238dcc)
entfernte die interne keep-Regel `-keepnames @dagger.hilt.android.lifecycle.HiltViewModel class * extends androidx.lifecycle.ViewModel`;
R8 Full-Mode entfernt dann den Ctor.
**Versionen:** beobachtet mit AGP 8.9.2 + Hilt 2.56.2; **weiterhin reproduzierbar mit Hilt 2.57.1 + KSP + AGP 8.9.1**
(User-Bestätigung Jan 2026). **gh-Status 2026-01-02: OPEN, kein offizieller Fix** — manuelle keep-Regel bleibt Pflicht.
**FIX (Regel manuell ergänzen):**
```proguard
-keep,allowobfuscation @dagger.hilt.android.lifecycle.HiltViewModel class * extends androidx.lifecycle.ViewModel { <init>(...); }
```
kapt→KSP-Migration reduziert generierte-Code-Probleme.
**Quelle:** [dagger#4739 (OPEN, gh-verifiziert)](https://github.com/google/dagger/issues/4739),
[dagger#4259](https://github.com/google/dagger/issues/4259).

### F2. WorkManager — Worker `ClassNotFoundException` im Release
**Ursache:** Default-WorkerFactory instanziiert Worker per Reflection über den Klassennamen; R8 obfuskiert/entfernt ihn.
**FIX:** WorkManager liefert eigene consumer-rules (greifen automatisch). Falls eigene Worker dennoch entfernt:
`-keep class * extends androidx.work.ListenableWorker { <init>(...); }`. Robust: **custom WorkerFactory**
mit explizitem Mapping (kein Reflection).
**Quelle:** [Jeroen Mols — WorkManager crash](https://jeroenmols.com/blog/2022/04/27/workmanager-crash/).

### F3. Firebase Firestore/RTDB — Modelle deserialisieren zu leeren Objekten
**Symptom:** Felder null/leer nach `toObject()`/`getValue(Class)`, oder „missing a constructor with no arguments".
**Ursache:** R8 entfernt no-arg-Ctor und/oder Felder/Getter (nur per Reflection genutzt).
**FIX:** Modelle mit `@Keep` annotieren, oder `-keepclassmembers class com.app.models.** { *; }`.
`@PropertyName`/`@DocumentId` brauchen erhaltene Namen. **Kotlin no-arg-Plugin NICHT mit Firebase mischen** (Inkompatibilität).
**Quelle:** [issuetracker #114554345](https://issuetracker.google.com/issues/114554345) (Status laut Quelle, unverifiziert).

### F4. Firebase Crashlytics — Stacktraces bleiben obfuskiert
**Ursache:** Altes Crashlytics-Gradle-Plugin inkompatibel mit AGP 8.1+; `mapping.txt`-Upload fehlt.
**FIX:** **Crashlytics-Gradle-Plugin v3.0.0+** (merged + lädt Mapping automatisch hoch), google-services-Plugin **4.4.1+**. NDK-Symbole separat.
Zusätzlich `-keepattributes SourceFile,LineNumberTable` für lesbare Zeilen.
**Falle beim v3-Upgrade (NEU):** Die Gradle-Felder `mappingFile`, `strippedNativeLibsDir` und die
`symbolGenerator`-Closure wurden in v3 **entfernt** → stehen sie noch in der Config, **bricht der Build**.
Fix: `mappingFile` löschen (Merge-Mapping kommt automatisch); `strippedNativeLibsDir` → `unstrippedNativeLibsDir`;
Closure → Top-Level-Felder `symbolGeneratorType` + `breakpadBinary`; Crashlytics-Extension von `defaultConfig`
in den **per-variant**-Scope verschieben.
**Quelle:** [Crashlytics deobfuscation docs](https://firebase.google.com/docs/crashlytics/android/get-deobfuscated-reports),
[Upgrade to Crashlytics Gradle plugin v3](https://firebase.google.com/docs/crashlytics/upgrade-to-crashlytics-gradle-plugin-v3).

### F5. Compose type-safe Navigation — Enum-Argument crasht im Release
**Symptom:** Production-Crash bei type-safe Routes mit Enum-Args (verschiedene Serializer-Instanzen).
**FIX (offiziell):** Enum-Argument-Klassen mit `@Keep` annotieren. Navigation **2.8.3** hat dafür einen Lint-Check.
Route-Klassen korrekt `@Serializable` + Serialization-Plugin.
**Quelle:** [Type-safe Navigation for Compose](https://developer.android.com/guide/navigation/design/type-safety),
[kotlinx.serialization#2825](https://github.com/Kotlin/kotlinx.serialization/issues/2825).

### F6. `@Preview`-Code landet im Release (Dev-Code/Mock-Daten)
**FIX (entfernt nur Dev-Code, funktionserhaltend für die App):**
```proguard
-checkdiscard class * { @androidx.compose.ui.tooling.preview.Preview <methods>; }
```

## G — Resource-Shrinking (`isShrinkResources = true`)

### G1. `Resources.getIdentifier()` — dynamisch geladene Ressource entfernt ⭐ HÄUFIG
**Symptom:** Per Name (`"ic_" + index`) geladene Drawables/Layouts/Raws fehlen im Release → Crash/leere UI.
**Ursache:** R8 sieht keine statische Referenz → entfernt die Ressource. (Safe-Mode behält nur String-Pool-Matches,
zusammengesetzte Namen greifen dort nicht.)
**FIX:** `res/raw/<package>.keep.xml` (Dateiname package-eindeutig!):
```xml
<?xml version="1.0" encoding="utf-8"?>
<resources xmlns:tools="http://schemas.android.com/tools"
    tools:keep="@drawable/ic_plus_anim_*,@raw/my_asset" />
```
**Quelle:** [Customize which resources to keep](https://developer.android.com/topic/performance/app-optimization/customize-which-resources-to-keep),
[issuetracker #37010152](https://issuetracker.google.com/issues/37010152).

### G2. `keep.xml` ohne `tools`-Namespace wirkungslos
`xmlns:tools="http://schemas.android.com/tools"` im `<resources>`-Tag MUSS gesetzt sein, sonst wird
`tools:keep`/`tools:discard` ignoriert.

### G3. `shrinkResources` ohne `minifyEnabled`
Resource-Shrinking setzt Code-Shrinking voraus → immer **beide** `true` (sonst Build-Fehler/ignoriert).

### G4. `tools:shrinkMode="strict"` bricht dynamische Auflösung
Strict entfernt alles nicht explizit Referenzierte (Theming-Engines, A/B-Test-/Plugin-Ressourcen).
Bei strict alle dynamischen Ressourcen einzeln in `tools:keep`. Default ist `safe`.

### G5. `resourceConfigurations`/`resConfigs` strippt Sprachen
`resourceConfigurations.addAll(listOf("en","fr"))` entfernt ALLE nicht-gelisteten Locales (auch aus Libs).
Falle bei i18n-Apps → alle wirklich unterstützten Locales auflisten oder weglassen.

### G6. `optimizedResourceShrinking` — Verhaltensänderung ab AGP 8.12 / Default ab 9.0
**Symptom:** Nach AGP-9.0-Upgrade werden Ressourcen aggressiver entfernt → dynamisch geladene können brechen.
**Ursache:** `android.r8.optimizedResourceShrinking` ist **opt-in ab 8.12**, **automatisch ab AGP 9.0** (Flag `=false`
dann deprecated). Statt safe/strict greift R8-getriebene statische Analyse.
**FIX:** Vor dem Upgrade Release gründlich testen; dynamische Ressourcen per `keep.xml` absichern.
**Quelle:** [Optimized resource shrinking (Google, Sep 2025)](https://android-developers.googleblog.com/2025/09/improve-app-performance-with-optimized-resource-shrinking.html).

## H — `-assumenosideeffects` / `-assumevalues` Fallen

### H1. Log-Calls entfernen — RICHTIG (funktionserhaltend)
```proguard
-assumenosideeffects class android.util.Log {
    public static *** d(...); public static *** v(...); public static *** i(...);
}
```

### H2. Wildcard `-assumenosideeffects ... { *; }` killt Synchronisation ⚠️ GEFÄHRLICH
**Symptom:** Bizarre Races/Deadlocks im Release.
**Ursache:** `-assumenosideeffects class android.util.Log { *; }` matcht die Hierarchie hoch bis `Object`
→ R8 darf `wait/notify/synchronized` als seiteneffektfrei entfernen.
**FIX:** **NIE `*`-Wildcard** — exakte Methoden-Signaturen angeben.
**Quelle:** [Jake Wharton — Value Assumption](https://jakewharton.com/r8-optimization-value-assumption/),
[Yazio — How to break your app with ProGuard/R8](https://medium.com/yazio-engineering/how-to-break-your-android-app-with-proguard-r8-6566bc387b63).

## I — keep-Regel Anti-Patterns

| Anti-Pattern | Problem | Richtig |
|--------------|---------|---------|
| `-keep class com.app.** { *; }` | Schaltet R8 fürs ganze Paket ab (App bläht auf, keine Optimierung), kostet weiter Build-Zeit | Member-Level, so eng wie möglich, `allowobfuscation` wo möglich |
| `-keep class !com.app.foo.** { *; }` | Negation invertiert: behält ALLES **außer** foo (Gegenteil der Absicht) | Präzise positive Regeln |
| Manuelle `-keep` für Activities/Services/Receiver | Redundant — in `proguard-android-optimize.txt` enthalten | Weglassen; nur nicht-im-Manifest-stehende reflektive Klassen brauchen Regeln |
| `-ignorewarnings` global | Versteckt echte Missing-Class-Fehler | Gezielt `-dontwarn com.lib.**` aus `missing_rules.txt` |
| `-if`-Backreferences (`<1>`,`<2>`) bei **doppelten** Wildcards (Klassen- UND Membername gewildcarded) oder negierten Wildcard-Namen in der Konsequenz | Backreference wird **still nicht aufgelöst** → keep greift nicht, Reflection bricht im Release | Bedingung so formulieren, dass nur EINE Wildcard-Ebene rückreferenziert wird; Membername konkret nennen ([AGP 9.2 Notes](https://developer.android.com/build/releases/agp-9-2-0-release-notes)) |

Quelle: [Configure and troubleshoot R8 keep rules (Google, Nov 2025)](https://android-developers.googleblog.com/2025/11/configure-and-troubleshoot-r8-keep-rules.html).

## K — Build-Performance: R8 OOM / StackOverflow

**K1. `OutOfMemoryError: Java heap space` in `minifyReleaseWithR8`** — R8 braucht für große Apps viel Heap.
**FIX:** `org.gradle.jvmargs=-Xmx4096m` (oder mehr) in `gradle.properties`; CI: `JAVA_TOOL_OPTIONS="-Xmx5g"`.
Über-breite keep-Regeln vermeiden (verhindern Optimierung großer Teile).
**K2. `StackOverflowError` beim Minify** — rekursive Optimierungspässe bei tief verschachteltem Code.
**FIX:** R8-Version per Dependency-Override aktualisieren; `fullMode=false` zum Eingrenzen.
**K3. `OutOfMemoryError: Required array length 2147483638 + N is too large` im `minifyReleaseWithR8`**
(NICHT „Java heap space" wie K1 — eigener Fehler, Heap-Erhöhung hilft NICHT). ⭐ **integrierter Resource-Shrinker**.
**Ursache:** Seit AGP **8.9** ist Resource-Shrinking in R8 integriert; R8 baut den Inhalt des
Proguard-**Mapping-Files als EINEN einzigen riesigen String** für den Resource-Shrinker auf → bei sehr
großen Apps (Richtwert ≥ 2000 Gradle-Module / großes Mapping) sprengt der String die max. Array-Länge.
**Betroffen:** AGP **8.9.0-alpha05/07/09** und **8.9.1** (8.8.x nicht betroffen).
**FIX:** Workaround ohne Downgrade — in `gradle.properties`: `android.r8.integratedResourceShrinking=false`.
Endgültig behoben in **R8 8.10.23** (in AGP **8.10.0** enthalten — Commit *„Don't build one giant string of
the mapping file content for resource shrinking"*). Betrifft nur 8.9.x → auf AGP 8.10.0+ heben.
**Quelle:** [Enable app optimization](https://developer.android.com/topic/performance/app-optimization/enable-app-optimization),
issuetracker [406525499](https://issuetracker.google.com/issues/406525499) (Fix R8 8.10.23), [149522381](https://issuetracker.google.com/issues/149522381).

## L — Multi-Modul / Library-Module / consumer-rules

- **L1.** `minifyEnabled` in Library-Modulen ist ab **AGP 8.4+ verboten** (Shrinking nur im App-Modul).
  Libs liefern Regeln per `consumerProguardFiles("consumer-rules.pro")`.
- **L2.** Globale Optimierungs-Flags (`-dontoptimize`/`-dontobfuscate`/`-repackageclasses`/`-allowaccessmodification`)
  in consumer-rules einer Lib leaken in die GANZE App (langsamer/größer/kaputt). **Ab AGP 9.0 ignoriert R8
  globale Opt-Flags aus Libs.** App kann problematische Lib-Regeln filtern:
  `release { optimization.keepRules { it.ignoreFrom("group:lib") } }` (AGP 9.0+).
- **L3.** keep-Regeln beim zugehörigen Code platzieren (im Lib-Modul, eng gescoped) — nicht alles im App-Modul.

## M — AGP-Upgrade-Breaking-Changes (Build bricht nach Upgrade)

| Ab Version | Änderung | Symptom | FIX |
|------------|----------|---------|-----|
| AGP 8.0 | `android.r8.failOnMissingClasses=true` erzwungen | „Missing class …" ist jetzt **Build-Fehler** (vorher Warnung) | Lib hinzufügen ODER gezielt `-dontwarn` aus `missing_rules.txt` (NICHT global `-ignorewarnings`) |
| AGP 9.0 | `proguard-android.txt` nicht mehr unterstützt | Schlecht optimiert / Build-Fehler | `getDefaultProguardFile("proguard-android-optimize.txt")` verwenden (Android Studio warnt schon) |
| AGP 9.0 | `optimizedResourceShrinking` automatisch | dyn. Ressourcen aggressiver entfernt | siehe G6 |
| AGP 9.0 | `android.r8.strictFullModeForKeepRules` default `true` | `-keep class A` impliziert **nicht mehr** den Default-Konstruktor → stille `NoSuchMethodException`/Reflection-NPE im Release | Bei Bedarf explizit `-keep class A { <init>(); }` |
| AGP 9.0 | `android.r8.globalOptionsInConsumerRules.disallowed` default `true` | **Library-Publishing schlägt fehl**, wenn Consumer-keep-Files globale Flags (`-dontoptimize`/`-dontobfuscate`) enthalten | Globale Flags ins App-Modul-`proguardFile` verschieben; `release { optimization.keepRules { it.ignoreFrom("group:lib") } }` als Übergang |
| AGP 9.2 | `-keepattributes *Annotation*` matcht **keine** RuntimeInvisible-Annotationen mehr (an D8 angeglichen) | Annotation-Frameworks brechen trotz `*Annotation*` | Explizit: `-keepattributes RuntimeInvisibleAnnotations,RuntimeInvisibleParameterAnnotations,RuntimeInvisibleTypeAnnotations` |

ProGuard→R8-Migration: `-optimizations`/`-optimizationpasses`/`-injars`/`-outjars`/`-dontpreverify` werden
unter R8 **still ignoriert**. Verhalten über keep-Regeln/`-assume*` steuern.

**Weitere R8-Changes in AGP 9.0.1 (Jan 2026, offizielle Release-Notes) — meist intern, zwei mit Wirkung:**
`-addconfigurationdebugging` wird **nicht mehr unterstützt** (entfernen, sonst Regel-Fehler); Default-Source-File
im Mapping ändert sich auf `r8-map-id-<MAP_ID>` (nur kosmetisch für `retrace`). Neu: `-processkotlinnullchecks`;
Keep-Info wird **nicht mehr an Companion-Methoden** propagiert; minimierte synthetische Namen im L8-Desugaring;
L8-Regel-Generierung aus D8/R8 entfernt. *Hinweis: `proguard-android-optimize.txt` wurde NICHT umbenannt
(Gerücht) — die Datei bleibt; nur `proguard-android.txt` fällt ab 9.0 weg (s. Tabelle).*
([AGP 9.0.1 Release-Notes](https://developer.android.com/build/releases/agp-9-0-0-release-notes))

## N — mapping.txt / Deobfuskation

- `mapping.txt` wird bei JEDEM Release-Build überschrieben → **pro veröffentlichter Version sichern/hochladen**.
- Für lesbare/eindeutige Stacktraces: `-keepattributes SourceFile,LineNumberTable` (R8 class-merging macht
  retrace sonst mehrdeutig).
- Auto-Deobfuskation in Android Studio ab Otter 3 / AGP 9.0; sonst `retrace` + gesichertes `mapping.txt`.
- **Mapping-Upload-Timing (Play Console):** `mapping.txt` ist im AAB automatisch enthalten (AGP 4.1+) und wird
  beim Upload assoziiert; Android Vitals deobfuskiert per ReTrace. ABER: nur Crashes/ANRs, die **NACH** dem
  Mapping-Upload für eine Version auftreten, werden deobfuskiert — vorher bleiben sie verschleiert. → Mapping
  muss schon im AAB sein, nicht nachträglich „repariert" werden. ([Deobfuscate stack traces](https://support.google.com/googleplay/android-developer/answer/9848633))
- **Native Debug Symbols (NDK) getrennt vom R8-Mapping:** `android.buildTypes.release.ndk.debugSymbolLevel =
  "SYMBOL_TABLE"` (oder `"FULL"`), automatisch im AAB ab AGP 4.1+. **Größenlimit ~300 MB** — bei `FULL`-Überschreitung
  wird der Upload abgewiesen → `SYMBOL_TABLE` verwenden. Prüfen ob Lib-`.so` schon gestrippt sind (info-Log
  „native debug metadata has already been stripped"). ([Native debug symbols](https://developer.android.com/build/include-native-symbols))
- **class/method-merging → mehrdeutiges retrace:** ein obfuskierter Frame mappt auf mehrere Original-Methoden;
  `# com.android.tools.r8.synthesized`-Annotationen in `mapping.txt` + `retrace --verbose` helfen beim Auflösen.

## P — Pflicht-Checkliste vor jedem Release mit R8

```
□ Release-Build (nicht Debug) gebaut UND auf echtem Gerät getestet — Debug beweist NICHTS über R8.
□ Alle reflektiv/serialisiert genutzten Modelle haben keep-Regeln (Gson/Moshi/Jackson/kotlinx/Firestore).
□ Enums mit valueOf()/values() gekeept (D1).
□ Parcelable CREATOR / JNI native / @JavascriptInterface gekeept falls genutzt (E1-E3).
□ Hilt @HiltViewModel keep-Regel gesetzt (F1, Bug ist OPEN).
□ Dynamisch per getIdentifier() geladene Ressourcen in <package>.keep.xml (G1).
□ minifyEnabled UND shrinkResources beide true (G3); resConfigs prüft i18n nicht weg (G5).
□ -assumenosideeffects ohne `*`-Wildcard, nur exakte Signaturen (H2).
□ Keine zu breiten -keep ... { *; }, keine Negation `!` (I).
□ missing_rules.txt geprüft und gezielt (nicht global) abgearbeitet.
□ mapping.txt für dieses Release gesichert + Crashlytics-Plugin v3+ (F4, N).
□ Bei AGP 8.7.3: ServiceLoader/META-INF/services genutzt? → #389737060 betrifft dich (O) — auf 8.9.1+ erwägen.
□ Nach AGP-Upgrade: missing-class-Fehler (8.0), proguard-android-optimize.txt (9.0), *Annotation* (9.2) beachten (M).
```
