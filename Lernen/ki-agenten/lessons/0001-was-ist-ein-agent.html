KI-Agenten bauen · Lektion 1

Was ein Agent ist, und was nicht

Danach erkennst du bei jedem KI-Programm in Sekunden, ob es ein einzelner Aufruf, ein Workflow oder ein Agent ist, und du kannst die Agenten-Schleife aus dem Kopf aufschreiben.

Etwa 10 Minuten · noch kein Code

Die eine Frage, die alles trennt

Du benutzt jeden Tag Agenten: Claude Code, Codex, OpenCode. Bevor du selbst einen baust, brauchst du eine scharfe Grenze. Sie hängt an einer einzigen Frage:

Prüffrage

Wer entscheidet, was als Nächstes passiert: dein Code oder das Modell?

Anthropic zieht die Grenze genau dort. Workflows sind Systeme, in denen Modelle und Werkzeuge über vorgegebene Code-Pfade gesteuert werden. Agenten sind Systeme, in denen das Modell seinen Ablauf und seine Werkzeugnutzung selbst lenkt.1

Stufe 1: der einzelne Aufruf

Du schickst Text hin, du bekommst Text zurück. Kein Werkzeug, keine Wiederholung. Das Modell steuert nichts.

Drei Beispiele
  • NewsKompass schickt eine Meldung ans Modell und bekommt eine Zusammenfassung in drei Sätzen.
  • Eine App lässt den Text „Speichern“ in zwölf Sprachen übersetzen.
  • Ein Programm fragt: „Ist diese Play-Store-Bewertung positiv, neutral oder negativ?“

OpenAI nennt solche Programme ausdrücklich keine Agenten: einfache Chatbots, einzelne Aufrufe, Stimmungs-Klassifizierer.2

Stufe 2: der Workflow

Mehrere Aufrufe hintereinander oder nebeneinander. Die Reihenfolge steht fest in deinem Code. Das Modell füllt nur die einzelnen Schritte.

Drei Beispiele
  • Kette: Text übersetzen, dann die Übersetzung von einem zweiten Aufruf prüfen lassen, dann formatieren. Immer diese drei Schritte.
  • Weiche: Ein erster Aufruf sortiert eine Frage in „leicht“ oder „schwer“. Leichte gehen an ein kleines Modell, schwere an ein großes.
  • Parallel: Dein Recherche-Schwarm. Das Skript startet sieben Researcher gleichzeitig, jeder bekommt ein festes Unterthema, am Ende wird zusammengeführt.

Anthropic beschreibt fünf solcher Bauformen: Kette, Weiche, Parallelisierung, Orchestrator mit Arbeitern, Erzeuger mit Prüfer.1 Die bekommen später eigene Lektionen.

Stufe 3: der Agent

Das Modell bekommt ein Ziel und eine Liste von Werkzeugen. Es entscheidet selbst, welches Werkzeug es wann benutzt, schaut sich das Ergebnis an und entscheidet dann den nächsten Schritt. Wie viele Schritte es werden, weiß vorher niemand.

Drei Beispiele
  • Claude Code soll einen Absturz beheben. Es liest Dateien, sucht im Code, ändert etwas, baut, liest den Fehler, ändert erneut.
  • Ein Helfer soll deinen Download-Ordner aufräumen. Er listet die Dateien auf, schaut in unklare hinein, verschiebt sie und prüft am Ende das Ergebnis.
  • Ein Agent in einer App soll „den günstigsten Zug nach Hamburg am Freitag“ finden. Er fragt Verbindungen ab, vergleicht, fragt bei Bedarf einen zweiten Tag ab.

Anthropic fasst es so zusammen: Agenten sind in der Regel nur Modelle, die Werkzeuge in einer Schleife benutzen, gestützt auf Rückmeldungen aus der Umgebung.1 Thorsten Ball, der einen Coding-Agenten in rund 300 Zeilen gebaut hat, sagt es noch kürzer: „It's an LLM, a loop, and enough tokens.“3

Die Schleife

Der wichtigste Satz dieser Lektion

Das Modell führt nie selbst etwas aus. Es schreibt nur einen Wunsch auf („rufe liste_dateien mit diesem Ordner auf“). Dein Code führt ihn aus und schickt das Ergebnis zurück.4

Beispiel A: zwei Runden, alles klappt

Ziel: „Wie viele Kotlin-Dateien hat NewsKompass?“

RundeWerWas passiert
1ModellWunsch: liste_dateien("NewsKompass", "*.kt")
1Dein Codeführt aus, hängt an: „212 Dateien“
2Modellkein Wunsch mehr, Antwort: „NewsKompass hat 212 Kotlin-Dateien.“ → fertig

Beispiel B: ein Werkzeug schlägt fehl

Ziel dasselbe, aber das Modell rät den falschen Ordner.

RundeWerWas passiert
1ModellWunsch: liste_dateien("Newskompas", "*.kt")
1Dein Codehängt den Fehler als Ergebnis an: „Ordner nicht gefunden. Vorhanden: NewsKompass, UpdateStation“
2Modellliest den Fehler, neuer Wunsch mit richtigem Ordner
2Dein Code„212 Dateien“
3ModellAntwort → fertig

Der Fehler wird nicht als Absturz behandelt. Er geht als Ergebnis zurück in die Schleife, und das Modell korrigiert sich. Je lehrreicher die Fehlermeldung, desto besser die Korrektur.5

Beispiel C: dein Code zieht die Notbremse

Das Modell verlangt Runde um Runde dasselbe Werkzeug mit denselben Angaben. Dieses Fehlbild ist schon in der Forschungsarbeit beschrieben, aus der das Schleifen-Prinzip stammt.6 Deshalb gehört in jede Schleife eine harte Obergrenze, zum Beispiel höchstens 20 Runden. Anthropic nennt ein Rundenlimit als übliche Abbruchbedingung.1 Von selbst ist sie oft nicht da: Im Claude Agent SDK gibt es standardmäßig kein Limit für Runden und Kosten.7

Wann du keinen Agenten baust

Ein Agent kostet mehr Zeit und Geld als ein einzelner Aufruf, und Fehler können sich über die Runden aufschaukeln. Anthropics Rat: die einfachste Lösung suchen und Komplexität nur dann erhöhen, wenn es nötig ist. Das kann heißen, gar kein agentisches System zu bauen.1

Drei Beispiele
  • Meldung zusammenfassen: ein Aufruf reicht. Ein Agent wäre langsamer und teurer, ohne besser zu sein.
  • Jede neue App-Bewertung übersetzen und einsortieren: immer dieselben zwei Schritte, also ein Workflow.
  • „Finde heraus, warum der Build seit gestern rot ist“: die Schritte sind nicht vorhersagbar. Hier lohnt der Agent.

Übung 1: einordnen

Stell dir bei jedem Fall die Prüffrage. Die Antworten stehen jedes Mal in anderer Reihenfolge.

Ein Skript holt jede Nacht die zehn neuesten Meldungen, lässt jede zusammenfassen und danach alle zehn zu einem Tagesüberblick verdichten.

Workflow. Die Reihenfolge (zehnmal zusammenfassen, dann verdichten) steht fest im Skript. Das Modell entscheidet nichts über den Ablauf.

Du sagst: „Finde in meinem Projekt alle Stellen, an denen noch der alte Keystore benutzt wird, und stell sie um.“ Das Programm sucht, liest, ändert und baut, so oft es nötig ist.

Agent. Welche Dateien es öffnet und wie viele Runden es braucht, entscheidet das Modell anhand der Ergebnisse.

Eine App schickt den Text einer Sprachnotiz ans Modell und zeigt die zurückgegebene Überschrift an.

Einzelner Aufruf. Text hin, Text zurück, kein Werkzeug, keine Wiederholung.

Ein Programm lässt ein Modell einen Text schreiben, ein zweites Modell bewertet ihn, und dein Code wiederholt das genau dreimal.

Workflow, obwohl es eine Schleife gibt. Entscheidend ist, wer über die Wiederholung bestimmt: hier dein Code, mit festen drei Durchgängen.

Ein Chat-Helfer hat die Werkzeuge „Kalender lesen“ und „Termin anlegen“. Auf „Schieb mein Treffen auf einen freien Platz am Donnerstag“ liest er erst den Kalender und legt dann den Termin an.

Agent. Niemand hat die Reihenfolge der Werkzeuge vorgegeben. Das Modell wählt sie anhand des Ziels und des Kalender-Ergebnisses.

Übung 2: aus dem Kopf

Schreib die vier Schritte der Schleife auf, ohne nach oben zu scrollen. Ergänze: Wann endet sie, und wer führt die Werkzeuge aus?

  1. Dein Code sendet den bisherigen Verlauf und die Werkzeugliste ans Modell.
  2. Das Modell antwortet mit Text oder mit einem Werkzeugwunsch.
  3. Dein Code führt das gewünschte Werkzeug aus.
  4. Dein Code hängt das Ergebnis an den Verlauf und beginnt wieder bei 1.

Ende: wenn das Modell kein Werkzeug mehr verlangt, oder wenn dein Code abbricht (Rundenlimit, Fehler). Die Werkzeuge führt immer dein Code aus, nie das Modell.
